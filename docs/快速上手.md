# Obsidian 笔记库医生 · 快速上手

写给**使用者**（不是开发者）。5 分钟跑通第一次体检。

---

## 一、它是什么

一个挂在对话里的 AI 专家。你说"帮我体检这个库"，它扫你本机的 Obsidian 库，
告诉你：**哪些问题该立刻修、哪些要你自己判断、哪些根本不用管**。

- 笔记不出你的电脑：脚本在你本机跑，不上传任何内容
- 零依赖：不需要装 Python 第三方库，有 Python 3.8+ 就行
- 可反悔：唯一会改文件的操作（移动/改名）自动备份，一条命令回滚

## 二、第一次体检（3 步）

**1. 打开对话，说：**

> 帮我体检这个 Obsidian 笔记库，告诉我先修什么

**2. 它会自动定位你的库。** 如果你开了库同步或多库，它会列出来让你选——
选你自己要查的那个。

**3. 等 10–60 秒**（几百篇的库通常 30 秒内），你会收到一份报告，长这样：

```
健康分：64 / 100

A 级 · 立刻能修（3 项）   ← 有唯一正确答案，可以放心让它修
B 级 · 要你判断（2 项）   ← 它只出建议，你拍板
C 级 · 不要动（4 类）     ← 看着像问题，其实是正常现象
```

**先只看 A 级。** B 级的东西读完再说，C 级跳过。

## 三、健康分怎么看

- 这是**它自己定的口径**（断链率、孤儿率、重复率、缺元数据率加权），不是行业标准
- **只能和自己比**：治理前 64 分，治理后 82 分，说明有改善
- 不要拿去和别人比，也没有"及格线"——60 分和 90 分的库都可以正常用
- 库不到 20 篇时分数意义有限，直接看清单就行

## 四、让它动手修（可选）

体检报告出来后，你可以说：

> 把 A 级修了

它会：
1. 先列出要动哪些文件，等你确认
2. 提醒你**关掉 Obsidian**（避免缓存冲突）
3. 移动/改名文件并自动改写全库链接，同时生成两个备份文件
4. 改完自查一遍，向你确认"差异归零"

**B 级它不会自动做。** 相似笔记合并、孤儿笔记去向这些没有标准答案，
它只会列出来问你。如果你发现它自作主张动了 B 级，这是 bug，回滚并反馈。

## 五、误操作自救指南 ⚠️

**任何改动之后，库里都会留下备份。** 想反悔：

1. 找到它最后一条消息里的**回滚命令**（长这样：`restore.py <库路径> <日志> <备份zip>`）
2. 原样发回给对话里，说"帮我回滚"
3. 它执行后向你确认"差异归零"

如果对话丢了、找不到命令了：
- 备份 zip 和 `change-log.csv` 默认在你库外面的工作目录里，找最近生成的两个文件
- 更坏的情况：Obsidian 本身有「文件恢复」插件（核心插件，默认开启），
  设置 → 文件恢复 → 快照，能找回历史版本
- **永远不要手动删整个文件夹**来"撤销"——那才是真正不可逆的操作

## 六、常见问题

**Q：和 Obsidian 自带的"未解析链接"面板有什么区别？**
A：Obsidian 原生只报断链，不报孤儿和重复，也不会区分"模板占位符"和真断链——
你会在面板里看到一堆模板假警报。这里给出的是排好序的分级方案 + 回滚能力。

**Q：会动我的 `.obsidian` 配置或插件吗？**
A：不会。`.obsidian/`、`.trash/`、`.git/` 全程不碰。

**Q：我的库 2000 篇，会卡吗？**
A：1200 篇实测：扫描 0.25 秒、体检 0.08 秒、重复检测 2 秒。相似度检测有
5000 篇上限保护，超大库会自动截断并明说。

**Q：模板里的 `[[示例]]` 被报成断链了？**
A：正常情况下不会——它会先识别模板目录和模板语法再豁免。如果识别漏了
（比如模板目录叫了个完全不相干的名字），如实告诉它"这是模板"，它会把
这条降级。识别错就直说，这是它的边界，报告里也写了。

**Q：两篇明明很像的笔记，为什么没被报成重复？**
A：它的重复检测偏保守（设计如此）：短笔记（几百字以内）改动较多时可能
落在"列出但不建议动"的档位。宁可漏报、不误报——把两篇独立笔记误标成
"可合并"的代价，远大于多看一眼的代价。完全相同（一字不差）的笔记
一定会被报出来。

**Q：两个库之间能迁移笔记吗？**
A：当前版本不做跨库操作。只治理单库。

**Q：隐私？**
A：扫描在本机完成，index.json 也存在本机。对话里你看到的统计数字
（多少篇、多少断链）不包含笔记正文。
