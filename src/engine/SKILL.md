# Obsidian Vault Engine

本 Skill 提供对 Obsidian 库的**只读诊断 + 安全变更 + 完整回滚**能力。
所有脚本跑在**用户本机**，纯 Python 标准库，**不需要 `pip install` 任何东西**。

---

## 0. 硬规则（每次任务开始前必读）

1. **先诊断，后动手。** 任何变更（move / 改名 / 删除）前必须先跑 `scan.py` 生成 `index.json`。没有 index 不许执行写操作。
2. **只读操作可以直接在用户真实库跑**：`vault.py`、`scan.py`、`health.py`、`dup.py`、`verify.py`。
3. **写操作必须先取得用户明确同意**，且必须先生成 `affected.zip` 备份 + `change-log.csv`，两者缺一不可。执行后必须告诉用户回滚命令。
4. **绝不删除用户文件。** 唯一允许的"删除"是移入库内 `.trash/`（记 `action=delete`，可回滚）。不要 `rm`，不要清空 `.trash`。
5. **不碰 `.obsidian/`、`.trash/`、`.git/`、`node_modules/`**——脚本已排除，但不要手动去改这些目录。
6. **无法确定就列人工复核，绝不猜。** Canvas 节点、跨库引用、插件私有语法（Dataview/Excalidraw）解析不到时，列成"人工复核项"，不要静默改或静默断链。
7. **内容不出本机。** 不把笔记正文、路径清单、诊断结果发到任何外部服务；只在本地读写。

## 1. 运行环境与授权

| 项 | 说明 |
|---|---|
| 执行位置 | **用户本机**。脚本读写的是本机文件系统上的 vault，不经任何服务器 |
| Python | WorkBuddy 自带 managed Python 即可；无第三方依赖（仅 `os/json/re/csv/shutil/zipfile/hashlib/argparse/datetime/collections`） |
| 网络 | 全程不需要联网 |
| 数据去向 | 仅本机。诊断产物（`index.json`、报告）写在用户指定目录，**不上传、不回传** |

**首次运行的授权声明（必须向用户明说一次）：**

> 这个引擎只在你本机运行：读取你库里的笔记文件做诊断，所有结果都写在你本地。
> 不会把笔记内容发给任何服务器。变更前会自动备份，随时可以用一条命令还原。

## 2. 定位库（第一步，永远先跑这个）

```bash
python3 scripts/vault.py            # 列出本机所有库：路径 / open 状态 / 篇数
python3 scripts/vault.py --auto     # 自动选库：只输出一个路径
python3 scripts/vault.py --json     # JSON 输出，便于解析
```

- 读的是 Obsidian 官方配置 `obsidian.json`（macOS / Windows / Linux 三平台路径均已适配）。
- `--auto` 在「只有一个库」或「只有一个库带 open 标记」时直接返回路径；**多库且无法判定时退出码 2**，此时必须把列表给用户，让用户选，不许自己挑一个。
- 找不到配置（退出码 1）→ 让用户直接提供 vault 路径。
- 库路径含空格/中文，命令里必须用双引号包起来。

## 3. 六个脚本，三组动作

### 组 A · 只读诊断（可对真实库直接跑）

```bash
# ① 全库扫描 → 基线 index.json（后续一切分析的唯一数据源）
python3 scripts/scan.py "<vault路径>" -o index.json

# ② 健康诊断 → 报告（断链 / 孤儿 / 缺 frontmatter / 重名 / 标签）
python3 scripts/health.py index.json                     # 打印到终端
python3 scripts/health.py index.json -o 健康报告.md      # 导出 Markdown

# ③ 重复候选打分（只出候选，绝不删除）
python3 scripts/dup.py index.json
```

`dup.py` 分档（判定口径写死，不要自行改阈值）：

| 相似度 | 标签 | 处置 |
|---|---|---|
| < 0.70 | 忽略 | 不展示 |
| 0.70 – 0.85 | 🔵 列出 | 只在报告里提一句 |
| 0.85 – 0.95 | 🟡 草案 | 可生成合并草稿，**必须用户确认** |
| 0.95 – 1.00 | 🟠 提案 | 生成合并提案 + diff 预览，**必须用户确认** |
| = 1.00（内容 hash 相同） | 🔴 可清理 | 仍需用户确认，动作是**移入 `.trash/`**，不是删除 |

> 注意：`dup` 用的是字符 3-gram shingle，对**短笔记**偏保守（内容 95% 相似可能只得 0.85 左右）。
> 短笔记场景要向用户说明"分数偏低是算法特性，不是没问题"，建议人工核对，不要因为分数低就断言不重复。
> 同名 ≠ 重复：判断重复只看内容，不看标题。

### 组 B · 写操作（必须先获用户同意 + 必须备份）

```bash
# ④ 移动 / 重命名 / 归档（单次）
python3 scripts/move.py index.json \
  --src "Inbox/旧笔记.md" --dst "Archive/旧笔记.md" \
  --backup affected.zip --log change-log.csv

# ④ 批量（先把方案写成 JSON 给用户看，确认后再执行）
python3 scripts/move.py index.json --plan plan.json \
  --backup affected.zip --log change-log.csv
```

`plan.json` 格式：

```json
{"operations": [{"src": "Inbox/a.md", "dst": "Archive/a.md"},
                {"src": "Inbox",     "dst": "Archive/Inbox"}]}
```

`move.py` 自动处理：
- 全库 `[[wikilink]]` 重写，保留别名 `[[x|别名]]`、heading `[[x#标题]]`、block `[[x#^块]]` 锚点；
- markdown 链接 `[文字](路径)` 与嵌入 `![[图片.png]]` 同步重写；
- **代码块（``` 围栏）与行内代码内的 `[[...]]` 一律不动**（视为示例文本）；
- Canvas `.canvas` 的 JSON `file` 字段专用重写；解析不到的列入"人工复核"；
- 目录级移动自动展开为逐文件映射（整个文件夹归档用它）；
- 目标落在 `.trash/` 时自动记 `action=delete`（去重清理语义，可回滚）。

### 组 C · 校验与回滚

```bash
# ⑤ 前后对比（移动后再 scan 一份，看结构级差异）
python3 scripts/scan.py "<vault路径>" -o index-after.json
python3 scripts/verify.py index-before.json index-after.json

# ⑥ 一条命令回滚
python3 scripts/restore.py "<vault路径>" change-log.csv affected.zip --index-before index-before.json
```

`verify.py` 输出：新增 / 删除 / 移动 / 断链增减 / 元数据覆盖变化。
**验收标准：治理前后 `broken_links` 不增加，`restore` 后 `verify` 差异为 0。**

`restore.py` 行为：解压 `affected.zip` 还原改前内容 → 逆序撤销 `change-log.csv` → 从 `.trash/` 还原 delete 项 → 清理 `create` 产生的残留文件 → 与 `index-before` 重扫比对。

## 4. 「30 秒体检卡」（首话必须交付的东西）

用户第一次问"我的库怎么样/乱不乱"时，**不要在 30 秒内讲方法论，直接跑 scan + health 出这张卡**：

> `health.py` 输出的是原始指标（终端或 `-o` 报告），**按下面格式重排后再给用户**，不要把原始输出直接抛出去。
> `health.py` 已经做了角色分档，卡片必须**保留两层结构**：
> **🎯 需要处理**只放真问题，**ℹ️ 已豁免**写明数量和原因。**不许把豁免项删掉不告诉用户**——
> 用户看到"没问题"时，必须能同时看到「引擎判断了哪些不属于问题、为什么」。

### 4.1 分档规则（为什么有些"问题"不算问题）

`scan.py` 给每篇笔记打了 `role`，`health.py` 按角色决定是否计入真问题：

| 角色 | 识别依据 | 断链 | 无入链 | 缺 frontmatter |
|---|---|---|---|---|
| `content` 正文 | 其他都不匹配 | 🎯 真问题 | 🎯 真问题 | 🎯 真问题 |
| `template` 模板 | ① `.obsidian` 配置的模板目录（核心模板插件 / Templater）② 目录名或文件名含"模板"（忽略 `99-` 这类排序前缀）③ `type: template` / tag ④ 正文含 `{{date}}`、`{{tp.xxx}}` 模板语法 | ℹ️ 占位符 | ℹ️ 豁免 | ℹ️ 豁免 |
| `archive` 归档 | 目录或文件名含 归档/快照/backup/副本/旧版 | ℹ️ 豁免 | ℹ️ 豁免 | ℹ️ 豁免 |
| `index` 索引页 | 库规/总览/导航/index/home/moc/README | 🎯 真问题 | ℹ️ 豁免 | 🎯 真问题 |
| `daily` 日记 | ① `daily-notes.json` / Periodic Notes 配置的目录 ② `type: daily` ③ 名字含 日记/日志/周报/daily ④ **名字就是日期**（`2026-10-22`、`2026-10-22 周三`）⑤ 目录名含日记词 ⑥ 目录整体是时间流（≥5 篇且 ≥50% 日期命名）时，日期前缀名才算日记 | 🎯 真问题 | ℹ️ 豁免 | 🎯 真问题 |

> **为什么第 ⑥ 条写得这么绕**：Zettelkasten 用户常用「`2026-09-01 闪念1.md`」命名原子卡片。
> 如果只看"文件名以日期开头就判日记"，这些**内容卡**会被豁免、孤儿被静默隐藏。
> 实测在 ZK 库上，早期实现因此漏报 12 篇孤儿（召回率只有 73.3%）。
> 现在要求**目录级证据**：整个目录都是日期名，才把日期前缀名算日记。
> 如果你看到用户的库是「全平铺 + 时间戳文件名」，孤儿检测是有效的，可以放心报。

**给用户解释时这么说**（这是产品的可信度所在）：
- 模板：模板里写的是待填的例子，链不到是设计如此
- 归档：留存副本不参与链接网络
- 索引页：库规/MOC 是链接的起点，不需要被谁链
- 日记：按日期命名，天然没人回链——**库用得越久这类越多**
- 系统垃圾文件（`.DS_Store`/`Thumbs.db`/`._xxx`）：已排除，不计入统计

### 4.2 卡片格式

```
┌─ 库体检卡 ──────────────────────────────
│ 库：<vault 路径>
│ 笔记 <N>（正文 <a> · 日记 <b> · 模板 <c> · 归档 <d> · 索引页 <e>）· 附件 <M>
├─ 🎯 需要处理（真问题 <n> 项）
│ 断链       <n> 处    ← 指向不存在的笔记（已排除模板占位）
│ 孤儿笔记   <n> 篇    ← 正文笔记没有任何入链
│ 缺元数据   <n> 篇
│ 重复       <n> 组    ← 内容完全相同 / 同名同内容
├─ ℹ️ 已豁免（<k> 类，不是库的病）
│ 模板占位链接 <n>（待填写，属正常）
│ 日记无入链 <n>（按日期命名，天然无回链）
│ 模板/归档无入链 <n>（按设计不被链接）
│ 归档缺元数据 <n>（快照性质）
│ 同名但内容不同 <n>（正常分类；用 [[文件名]] 写链接会有歧义，建议带路径）
│ 系统垃圾文件 <n>（.DS_Store 等，已排除）
├─ 判断
│ <一句话：这个库处在什么状态，最该先做哪一件事>
└─────────────────────────────────────────
```

**大库注意**：同类问题超过 15 条时，`health.py` 终端输出已按两级目录聚合
（如 `20-领域知识/产品设计/ → 14 篇`）。给用户时保留聚合形式，别展开成几十行文件名；
需要逐条清单就 `-o` 导出报告。

### 4.3 状态分档（决定后面推荐什么动作，**不要跳档**）

| 条件 | 状态判定 | 建议 |
|---|---|---|
| 笔记 ≤ 100 篇 且 断链率 < 10% | **建库期** | 先建规范（模板 + 少量看板），不做大改造 |
| 100–2000 篇，或有明显无入链堆积 | **治理期** | 定一个结构（只选一种），分批迁移 |
| > 2000 篇 或 断链率 ≥ 20% | **抢救期** | 先修断链，再谈结构；不做批量重命名 |

断链率 = **真断链数** ÷ 链接总数（模板占位符不计入分子）。

## 5. 操作卡 · 治理执行前（写操作必跑这段检查）

执行 `move.py` / 任何写操作**之前**，逐条确认并向用户明说：

1. **请先关闭 Obsidian（至少关闭正在编辑的标签页）。** 原因：Obsidian 文件监听器会缓存旧路径，脚本在外部改文件的同时它可能回写，导致链接重写被覆盖或出现编辑冲突。改完再打开即可。
2. **确认库没有正在同步**（iCloud / OneDrive / 坚果云）。同步冲突会产生 `conflicted copy` 文件，与本次变更混在一起难以回滚。建议暂停同步或确认已同步完成。
3. **确认已生成备份**：`affected.zip`（受影响文件改前内容）+ `change-log.csv`（动作日志）。两个文件都要存在且非空。
4. **向用户报出本次变更清单**：移动几个文件、重写几个引用者、有几个 canvas 需要人工复核——先报数，再执行。
5. **执行完立即给出回滚命令**（上面组 C 第 ⑥ 条原样贴出）。

## 6. 标准任务流程

**诊断类（只读，最常用）**
```
vault.py --auto → scan.py → health.py → 出体检卡 → 等用户决定
```

**整理类（写操作）**
```
vault.py --auto → scan.py(index-before) → 出方案给用户确认
  → [操作卡 §5 检查] → move.py --plan → scan.py(index-after) → verify.py
  → 报结果 + 给回滚命令
```

**去重类**
```
scan.py → dup.py → 按分档出候选 → 用户逐组确认
  → move.py --src <重复文件> --dst .trash/<文件名> （记 delete）
  → verify.py
```

流程中断了怎么办：`index.json` 和 `change-log.csv` 都在，重新跑 `restore.py` 即可回到改前状态；不要手动拼回去。

## 7. 边界与降级（不确定就明说，不许硬撑）

| 场景 | 处理 |
|---|---|
| Canvas 节点引用解析不到 | 列"人工复核项"，不改、不删、不静默断链 |
| 跨 vault 引用（`[[../另一个库/x]]`） | **不支持**，明确告知用户超出范围 |
| Dataview / Excalidraw / Templater 私有语法 | 视为普通文本，不解析不重写；命中时列入复核 |
| 文件名含 `#`（如 `Note #1.md`） | 已支持：先按完整文件名解析，失败才拆 anchor |
| 文件名含点（如 `手册-v5.0.2-快照.md`） | 已支持：只认 `.md`/已知附件扩展名为真扩展名 |
| Windows / Linux | 脚本用正斜杠 + utf-8 `errors=replace`；**未在 Windows 实测**，遇到异常如实告知，不要声称已支持 |
| 超大库（>5000 篇） | scan 是流式遍历但仍是单进程；先告知预估耗时，不要假装秒回 |
| **角色判定可能误判** | 模板/归档/索引/日记靠 `.obsidian` 配置 + 命名 + frontmatter + 内容特征四重判断。仍有一种情况会误判：模板目录名字怪异（如 `_素材`）且模板正文里没有任何 `{{date}}` 类变量 → 会被当正文、其占位链接报成断链。**发现体检卡里的"断链"明显是模板例子时，如实告诉用户"这几条疑似模板占位，我按断链报了，你可以忽略"，不要硬说库有问题** |
| 用户目录结构极端特殊 | 分档不适用时（如全库都是日记），如实说明"你的库以时间流为主，孤儿指标对你意义不大"，改看别的问题 |

> **三种库结构已实测**（PARA 多级目录 / Zettelkasten 全平铺双链 / 纯时间流），
> 断链·孤儿·重复 三项检测均为 100% 召回 + 100% 精确。详见 `压测报告-v2.md`。
> 若用户库明显不属于这三类（如纯白板库、纯附件库），先说明"这类结构我经验有限"再给结论。

## 8. 结果呈现

- 诊断结果：**体检卡（§4）+ 最多 3 条建议**，不写长文。
- 变更结果：改了几个文件 / 重写了几处链接 / 断链增减 / 需要人工复核的条目 / 回滚命令。
- 永远不要用"完美""彻底解决""全自动无忧"这类词；如实报数量与残留问题。
